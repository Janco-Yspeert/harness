# Human Implementation Correction Authority

Spike 014g attempts 009 and 010 are preserved unchanged as `BLOCKED / INFRASTRUCTURE_FAILURE`.

They established that evaluator revision `003` requires candidate-subject evidence that the currently accepted 014i subject mechanism cannot produce: an exact frozen evaluator procedure must be supplied together with host-created topology and host-side before/after observations without exposing evaluator-private procedure bytes to the public supervisor.

This is accepted as an implementation gap in the current Harness candidate-subject mechanism.

I authorize one bounded Implementation correction to address that gap.

The correction is limited to extending the existing accepted 014i candidate-evaluator-subject mechanism so the host can resolve and execute already-authorized frozen evaluator material by exact evaluator-revision/procedure identity, together with host-created observation inputs, while preserving the existing 014h containment and 014i non-authoritative-subject guarantees.

The correction must not:

- change the frozen 014g brief, Design Map, or evaluator revision `003`;
- rewrite or reinterpret attempts 009 or 010;
- expose evaluator-private procedure contents to the public Implementation worker, supervisor, or candidate authority;
- introduce arbitrary private-file, secret, or host-path injection;
- create a second candidate-subject engine;
- change model-selection semantics, promotion/archive policy, or unrelated Harness architecture;
- expand into general prompt injection, session continuation, or WAITING_FOR_HUMAN redesign.

The Implementation worker may receive this recorded decision as the authoritative sanitized correction requirement.

If production code changes, the resulting implementation-handoff commit becomes a new candidate C3. C2 and all C2-bound evidence remain immutable history.

This is a bounded human recovery decision for Spike 014g. It does not establish a general methodology rule or permanent recovery mechanism.

The lack of a first-class governed human implementation-correction input is deferred for successor work after Spike 014.
